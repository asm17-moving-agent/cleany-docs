# 260803 - 다중 객체 폐루프 책상 정리 시나리오

## 목적

여러 물체가 있는 책상에서 ER 2가 한 번의 정답을 내고 끝나는 것이 아니라,
관찰→계획→실행→재관찰을 반복하는 적용 예시다. 이 문서는 확정 운영 정책이나
성공 기준이 아니다.

## 예시 장면

```text
종이컵 1개
캔 1개
휴지 1개
개인 소지품으로 보이는 물체 1개
```

쓰레기 후보는 로봇 탑재 수거함으로 옮기는 대상이다. 개인 소지품으로 보이는
분실물 후보의 물리적 행동은 정해지지 않았으므로 예시에서도 목적지를 가정하지 않는다.

## 폐루프 흐름

1. Mission Manager가 대상 좌석 도착을 확인한다.
2. 작업 전 RGB-D 관찰을 저장한다.
3. ER 2가 물체 후보, 의미, 처리 가능 여부와 작업 순서를 제안한다.
4. 로컬 Guard가 tool 이름, argument, 객체 ID와 현재 상태를 검증한다.
5. 승인된 Manipulation Skill 하나를 실행한다.
6. Skill 내부 VLA policy 또는 motion backend가 arm·gripper action을 생성한다.
7. 로컬 안전 계층이 limit·collision·timeout을 강제한다.
8. 실행 결과와 최신 관찰을 ER 2에 돌려준다.
9. 남은 물체에 대해 3~8을 반복하거나 완료·실패로 종료한다.
10. 작업 후 관찰을 저장하고 Mission Manager가 복귀·보고를 수행한다.

## Planner 출력 예시

```json
{
  "scene_id": "seat-07-before",
  "ordered_tasks": [
    {"object_id": "tissue-1", "capability": "collect_trash"},
    {"object_id": "can-1", "capability": "collect_trash"}
  ],
  "unresolved_objects": ["personal-item-1"]
}
```

이 형식은 개념 예시이며 ROS schema가 아니다. 실제 schema는 구현 코드와 패키지
README에서 관리한다.

## 실패와 정지

- Skill 실패 시 같은 물체의 재시도·skip·미션 중단 정책은 별도 정의한다.
- ER 2의 응답이 없거나 유효하지 않으면 새 물리 행동을 시작하지 않는다.
- safe stop과 e-stop은 ER 2 tool 호출과 독립적으로 동작한다.
- 사람 존재 시 행동은 아직 결정하지 않았으며, 현재 데모는 사람이 없는 통제 구역을
  전제로 한다.
