# 260803 - 다중 객체 폐루프 책상 정리 시나리오

## 출처

- [ChatGPT 공유 문서: Gemini Robotics ER 2](https://chatgpt.com/share/6a6f8bd0-8ab8-83ee-bee5-081c013dd3bc)

## 1. 시나리오 전제

공유 답변의 마지막 다중 객체 시나리오를 기준으로 한다. 작업 시작 시 시스템은 책상
위에 무엇이 있는지 모른다. 실제 장면에는 다음 객체가 있다고 가정한다.

```text
펜 2개
컵 1개
지우개 1개
휴지 뭉치 1개
```

정리 정책 예시는 다음과 같다.

```text
분실 가능성이 있는 재사용 물품 → 분실물함
명백한 쓰레기 → 쓰레기통
판단 불가능한 물체 → 건드리지 않음
내용물이 확인되지 않은 용기 → 이동하지 않음
한 번에 한 물체만 이동
각 이동 직후 결과 검증
사람이 작업 영역에 들어오면 정지
```

이 분류와 목적지는 공유 답변의 예시이며 Cleany 운영 정책으로 확정되지 않았다.

## 2. 전체 흐름

```text
[Device]       안전 상태 검사
    ↓
[Camera]       RGB-D 책상 촬영
    ↓
[Edge → ER 2]  RGB 이미지·정책·최초 인벤토리 프롬프트
    ↓
[ER 2 → Edge]  객체 후보·2D 위치·임시 분류
    ↓
[Edge]         mask·Depth·3D pose·graspability 계산
    ↓
[Edge → ER 2]  객체별 의미·3D 상태·안전 정보
    ↓
[ER 2 → Edge]  다음 고수준 동작 하나
    ↓
[Device]       파지·모션·실행·재검증
    ↓
[Device → ER2] tool result와 최신 장면
    ↓
[ER 2]         다음 물체 또는 검사·skip·완료
```

## 3. 작업 명령과 초기 상태

사용자 명령:

```text
책상 위를 정리해.

분실물은 분실물함에 수거하고,
쓰레기는 쓰레기통에 버려.
판단이 안 되는 물체는 건드리지 마.
안전하고 효율적인 순서로 하나씩 처리해.
```

Edge Orchestrator 상태:

```json
{
  "task_id": "desk_cleanup_20260801_001",
  "state": "INITIALIZING",
  "known_objects": [],
  "completed_objects": [],
  "skipped_objects": []
}
```

## 4. ER 2 호출 전 로컬 안전 점검

다음 항목은 ER 2보다 먼저 로컬에서 확인한다.

- 비상 정지 해제 여부
- 로봇 driver와 controller 상태
- 그리퍼 초기화와 개폐 여부
- RGB-D 카메라와 frame 동기화 여부
- 사람의 작업 영역 진입 여부
- 카메라–로봇 calibration 유효 여부
- 분실물함과 쓰레기통의 사용 가능 여부

```json
{
  "robot_ready": true,
  "camera_ready": true,
  "gripper_ready": true,
  "human_in_workspace": false,
  "lost_found_bin_available": true,
  "trash_bin_available": true
}
```

하나라도 실패하면 새 작업을 시작하지 않는다.

## 5. 최초 장면 촬영

```json
{
  "scene_id": "scene_001",
  "rgb_frame": "rgb_001.jpg",
  "depth_frame": "depth_001.raw",
  "resolution": {
    "width": 1280,
    "height": 720
  },
  "camera_frame": "camera_color_optical_frame",
  "robot_frame": "base_link"
}
```

RGB JPEG는 ER 2에 전달할 수 있지만 Depth 원본은 로컬에서 처리한다. ER 2에는
필요할 때 3D 좌표, 크기, pose 품질과 graspability를 JSON으로 전달한다.

## 6. 최초 인벤토리 요청

프롬프트가 요구할 항목:

```text
- 보이는 독립 이동 가능 객체를 빠짐없이 후보화
- 임시 object ID와 semantic label
- 0~1000 정규화 2D point와 bbox
- lost_property, trash, unknown 중 임시 분류
- 분류 confidence
- 필요한 추가 검사
- 눈에 보이는 위험 요인
- 보이지 않는 객체를 만들지 않음
- motor command나 joint position을 생성하지 않음
```

답변 예시의 핵심 출력은 다음과 같다.

| object ID | label | 임시 분류 | confidence | 추가 검사·위험 |
| --- | --- | --- | ---: | --- |
| `pen_01` | black pen | lost property | 0.98 | graspability |
| `pen_02` | blue pen | lost property | 0.97 | graspability |
| `cup_01` | ceramic cup | lost property | 0.91 | contents, fragility, graspability |
| `eraser_01` | white eraser | lost property | 0.96 | graspability |
| `tissue_01` | crumpled used tissue | trash | 0.97 | deformable, graspability |

예시 bbox:

```json
{
  "object_id": "tissue_01",
  "label": "crumpled_used_tissue",
  "point_2d": {
    "y": 612,
    "x": 774
  },
  "bbox_2d": {
    "y_min": 559,
    "x_min": 728,
    "y_max": 663,
    "x_max": 828
  },
  "preliminary_class": "trash",
  "classification_confidence": 0.97,
  "required_inspections": [
    "graspability"
  ],
  "visible_risks": [
    "deformable"
  ]
}
```

이 출력만으로 물리 동작을 시작하지 않는다.

## 7. 로컬 mask·Depth·3D 계산

```text

→ 로컬 segmentation
→ 객체 mask
→ mask 내부 유효 Depth와 이상치 제거

→ camera frame의 3D 위치·방향
→ calibration transform
→ base_link 기준 pose
```

## 8. 우선순위 계획

ER 2에는 의미 분류와 함께 로컬에서 계산한 graspability, path clear, contents와
fragility를 전달한다. 답변은 다음 우선순위 기준을 예시로 제시했다.

1. Unknown 또는 unsafe object는 이동하지 않는다.
2. 높은 분류 confidence를 우선한다.
3. 접근 경로가 분명하고 파지 가능한 물체를 우선한다.
4. 다른 물체의 접근을 가리는 물체를 먼저 처리한다.
5. 목적지가 같으면 합리적인 범위에서 묶는다.
6. fragile container는 단순 rigid object 이후에 다룬다.
7. 한 번에 한 물체만 이동하고 매번 검증한다.
8. 관절 좌표와 grasp pose는 ER 2가 생성하지 않는다.

답변의 계획 예시는 다음 순서다.

```text
1. tissue_01 → trash_bin
2. eraser_01 → lost_found_bin
3. pen_01 → lost_found_bin
4. pen_02 → lost_found_bin
5. cup_01 → inspect contents·fragility·graspability
```

전체 계획을 받더라도 실행은 첫 tool call 하나만 승인한다.

## 9. 휴지 뭉치 처리

ER 2 tool call:

```json
{
  "tool_call": {
    "id": "call_001",
    "name": "move_object",
    "args": {
      "object_id": "tissue_01",
      "destination": "trash_bin",
      "handling_profile": "deformable_waste"
    }
  }
}
```

로컬 시스템은 실행 직전 최신 mask와 Depth를 다시 계산하고, 변형 물체용 낮은 힘의
top-down grasp와 충돌 없는 trajectory를 선택한다.

```json
{
  "object_id": "tissue_01",
  "selected_grasp": {
    "position": [0.592, -0.182, 0.758],
    "approach_vector": [0.0, 0.0, -1.0],
    "gripper_width_m": 0.054,
    "grip_force_n": 6.0
  },
  "trajectory": {
    "collision_free": true,
    "joint_limits_valid": true,
    "estimated_duration_s": 4.8
  }
}
```

실행 후 원 위치에서 휴지가 사라졌는지, 쓰레기통에서 확인되는지, 다른 물체가
움직이지 않았는지 검사하고 tool result를 반환한다.

## 10. 지우개와 펜 처리

지우개와 펜은 `rigid_small` handling profile을 사용한다.

```text
최신 pose 확인
→ top-down grasp 후보 생성
→ SO-101 reachability·충돌 검사
→ 분실물함으로 이동
→ source empty·destination confirmed 검증
→ tool result 반환
```

펜은 긴 축을 추정해 그 축과 수직으로 그리퍼를 정렬하고 중앙부를 잡는 예시가
제시됐다. 지우개는 OBB 중심과 짧은 축을 기준으로 top-down 파지를 사용한다.

```json
{
  "object_id": "pen_01",
  "grasp": {
    "type": "top_parallel_grasp",
    "gripper_width_m": 0.018,
    "approach_vector": [0.0, 0.0, -1.0]
  },
  "trajectory_valid": true
}
```

한 물체가 실패하면 다음 물체로 조용히 넘어가지 않는다. 위치 불확실 여부를 포함한
실패 결과를 ER 2에 보내 재스캔·재시도·skip·사람 개입 중 하나를 선택하게 한다.

## 11. 컵 추가 검사

컵은 바로 이동하지 않고 `inspect_object`를 호출한다.

```json
{
  "tool_call": {
    "id": "call_005",
    "name": "inspect_object",
    "args": {
      "object_id": "cup_01",
      "checks": [
        "contents",
        "fragility",
        "graspability"
      ]
    }
  }
}
```

검사 과정 후보:

```text
컵 위 안전 관찰 자세로 이동
→ 손목 카메라 또는 추가 시점 촬영
→ 액체 표면·내용물 확인
→ 컵 기울기·파손 여부 확인
→ 손잡이와 본체 파지 가능 영역 확인
```

빈 컵 예시:

```json
{
  "object_id": "cup_01",
  "contents": {
    "state": "empty",
    "confidence": 0.94
  },
  "fragility": {
    "state": "fragile",
    "material": "ceramic"
  },
  "graspability": {
    "graspable": true,
    "preferred_grasp": "body_side_grasp",
    "quality": 0.78
  },
  "upright": true
}
```

## 12. 컵 이동과 5-DOF 제약

검사 통과 시 `fragile_upright` 프로필로 이동을 요청한다. 로컬 모션 계획은 다음
제약을 적용한다.

```json
{
  "object_id": "cup_01",
  "constraints": {
    "keep_upright": true,
    "max_tilt_degrees": 5,
    "max_speed_mps": 0.10,
    "max_acceleration_mps2": 0.20,
    "max_grip_force_n": 10
  },
  "selected_grasp": {
    "type": "body_side_grasp",
    "gripper_width_m": 0.086
  },
  "trajectory_valid": true
}
```

SO-101이 5-DOF이므로 upright와 위치·접근 방향을 동시에 만족하는 IK가 없을 수 있다.
이 경우 자세 제약을 무리하게 풀어 실행하지 않고 `not_graspable` 또는
`unsafe_to_move`로 남긴다.

## 13. 판단 불가능한 분기

컵 내용물 검사 결과가 `unknown`, confidence 0.51이라면 이동하지 않는다.

```json
{
  "tool_call": {
    "id": "call_006_alt",
    "name": "skip_object",
    "args": {
      "object_id": "cup_01",
      "reason": "contents_unknown"
    }
  }
}
```

ER 2가 실수로 이동을 요청해도 로컬 정책이 차단한다.

```python
if obj.is_container and obj.contents != "empty":
    return {
        "status": "rejected",
        "reason": "container_contents_not_verified",
    }
```

## 14. 최종 재스캔과 완료

모든 허용 물체 처리 후 RGB-D로 전체 책상과 목적지를 다시 스캔한다.

```json
{
  "scene_id": "scene_final",
  "desk_objects": [],
  "destinations": {
    "trash_bin": [
      "tissue_01"
    ],
    "lost_found_bin": [
      "eraser_01",
      "pen_01",
      "pen_02",
      "cup_01"
    ]
  },
  "unhandled_objects": []
}
```

완료 조건:

- 높은 confidence의 trash가 쓰레기통에 있다.
- 높은 confidence의 lost property가 분실물함에 있다.
- Unknown·unsafe object는 움직이지 않았다.
- 의도하지 않은 다른 객체 이동이 없다.
- 책상에 처리 가능한 대상이 남지 않았다.

ER 2 구조화 출력 예시:

```json
{
  "task_status": "completed",
  "moved_objects": [
    {
      "object_id": "tissue_01",
      "classification": "trash",
      "destination": "trash_bin"
    },
    {
      "object_id": "eraser_01",
      "classification": "lost_property",
      "destination": "lost_found_bin"
    },
    {
      "object_id": "pen_01",
      "classification": "lost_property",
      "destination": "lost_found_bin"
    },
    {
      "object_id": "pen_02",
      "classification": "lost_property",
      "destination": "lost_found_bin"
    },
    {
      "object_id": "cup_01",
      "classification": "lost_property",
      "destination": "lost_found_bin"
    }
  ],
  "skipped_objects": [],
  "remaining_actionable_objects": 0,
  "summary": "Desk cleanup completed."
}
```

## 15. 실패 상태도 완료 결과에 포함

실제 최종 상태는 `completed`, `partially_completed`, `failed`를 구분한다. Unknown,
내용물 미확인, 파지 불가, 사람 접근, API 단절 또는 목적지 가득 참으로 건드리지 않은
객체는 `skipped_objects`에 이유를 기록한다. “책상에서 모든 물체가 사라짐”만을 완료
조건으로 사용하지 않는다.
