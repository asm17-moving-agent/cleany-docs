# 260803 - 시스템 아키텍처와 책임 경계

## 핵심 구조

```text
Dashboard / Backend
        ↓ Mission Request
Mission Manager
├─ Navigator
├─ Desk Task Planner: ER 2 또는 RuleBasedPlanner
├─ Robot Capabilities
│  ├─ Navigation
│  └─ Manipulation Skills (VLA-backed 포함 가능)
└─ Reporter

Safety Controls ── 모든 실행을 선점할 수 있는 독립 경로
```

현재 구현에서는 Mission Manager가 Navigator를 직접 호출한 뒤 책상 작업 Planner와
Skill Executor를 호출한다. 목표 구조에서 ER 2가 Navigation tool까지 선택할지는
열린 질문이다.

## 계층별 책임

| 계층 | 책임 | 하지 않는 일 |
|---|---|---|
| Mission Manager | 미션 상태, 단계 전이, 실패·보고 | 장면 의미 해석, motor 제어 |
| Navigator | 대상 좌석 이동과 복귀, Nav2 결과 반환 | 책상 물체 처리 순서 결정 |
| ER 2 Planner | 장면 해석, 대상·순서·다음 tool 제안 | trajectory와 안전 제한 강제 |
| RuleBasedPlanner | 같은 Planner 계약의 E2E 통합 검증 | 목표 AI 성능 대체 |
| Manipulation Skill | arm·gripper를 이용한 물리 작업 | Mission 상태 직접 변경 |
| VLA policy | Manipulation Skill 내부의 learned action 생성 | 전체 미션·Navigation 소유 |
| Robot Interface | Sim·Real 공통 실행·상태 경계 | 작업 의미 재해석 |
| Safety Controls | timeout, limit, safe stop, e-stop | 확률적 Planner 승인 대기 |

## Skill과 VLA

Cleany의 Manipulation Skill은 반드시 고정 trajectory만 의미하지 않는다. 하나의
high-level skill이 VLA policy, MoveIt·controller 또는 둘의 조합으로 구현될 수 있다.
Skill 계약은 backend와 무관하게 목표, 허용 조건, 결과와 취소 가능성을 표현한다.

예시:

```text
collect_trash(object_id)
  ├─ VLA policy가 arm action 생성
  ├─ 로컬 limit·collision·workspace guard
  ├─ gripper·arm 실행
  └─ success / failed / blocked 결과
```

## Stop 경계

- `pause/cancel`: Mission Manager가 미션 또는 현재 action을 취소하는 제어 계약
- `safe stop`: Safety Monitor·Robot Interface가 현재 동작을 선점하는 로컬 기능
- `e-stop`: AI와 일반 ROS 실행 경로를 우회하는 물리적 최우선 경로

ER 2에 정지 요청 tool을 제공할 수는 있지만 실제 정지 권한을 ER 2 호출 성공에
의존시키지 않는다.
