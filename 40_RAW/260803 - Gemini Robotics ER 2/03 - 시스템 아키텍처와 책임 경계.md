# 260803 - 책상 정리 시스템 아키텍처와 책임 경계

## 출처

- [ChatGPT 공유 문서: Gemini Robotics ER 2](https://chatgpt.com/share/6a6f8bd0-8ab8-83ee-bee5-081c013dd3bc)

## 1. 핵심 결론

```text
ER 2는 장면의 의미와 다음 작업을 결정한다.
로컬 로봇 스택은 실제 위치와 실행 방법을 계산한다.
Edge Orchestrator는 두 결과를 연결하고 실행 결과를 다시 ER 2에 전달한다.
```

```text
사용자 명령·정리 정책
        ↓
Gemini Robotics ER 2
- 장면 의미 이해
- 객체 분류와 우선순위
- 다음 작업 결정
- 실행 결과 해석·재계획
        ↓ 구조화된 작업 요청
Edge Orchestrator
- schema·정책 검증
- 로컬 모듈 호출
- 결과 연결·기록
        ↓
로컬 로봇 스택
- 객체 mask·ID·3D pose
- grasp·trajectory 계산
- 로봇 실행·결과 확인
        ↓
최신 장면·구조화된 실행 결과
        └──────────────────► ER 2
```

## 2. 계층별 책임

| 계층                | 입력                                   | 출력                               | 책임 범위 밖                        |
| ----------------- | ------------------------------------ | -------------------------------- | ------------------------------ |
| ER 2              | 사용자 명령, RGB 이미지, 객체 요약, 작업 정책, 실행 결과 | 의미 분류, 우선순위, 다음 작업 요청, 완료 판단     | 최종 3D 좌표, grasp, 관절 trajectory |
| Edge Orchestrator | ER 2 출력, 객체 레지스트리, 로컬 실행 결과          | 검증된 모듈 요청, 연결된 결과, 이벤트 기록        | 이미지·Depth 원시 처리, 직접 모션 계산      |
| Local Perception  | RGB-D, 카메라 정보, 관심 객체 후보              | mask, object ID, 3D pose, 크기와 품질 | 작업 우선순위와 목적지 결정                |
| Grasp·Motion      | 객체 형상, pose, 로봇 제약, 목적지              | grasp 후보, IK, trajectory, 실행 결과  | 객체의 의미 분류                      |
| Robot Interface   | trajectory와 gripper 명령               | joint·gripper 상태, 성공·실패 결과       | 작업 계획과 재시도 판단                  |

## 3. ER 2와 로컬 시스템의 데이터 경계

### ER 2로 전달할 정보

- 사용자 명령과 작업 정책
- RGB 이미지 또는 필요한 crop
- object ID와 의미·위치의 요약 정보
- 직전 작업의 성공·실패와 관찰 결과
- 현재까지 처리한 객체와 남은 객체 요약

### 로컬에 유지할 정보

- Depth 원본과 전체 point cloud
- 카메라 보정값과 frame transform
- 고주기 joint·gripper 상태
- 최종 3D pose와 grasp 후보
- IK 결과와 trajectory
- 장치별 오류와 제어 상태

ER 2에는 의미 판단과 다음 작업 선택에 필요한 정보만 전달한다. 계측과 모션 계산에
필요한 고빈도·대용량 데이터는 로컬에서 처리한다.

## 4. 객체 레지스트리

객체 레지스트리는 ER 2의 의미 판단과 로컬 계측 결과를 같은 `object_id`로 연결한다.

```json
{
  "object_id": "object_01",
  "semantic_label": "mug",
  "task_category": "lost_property",
  "classification_confidence": 0.92,
  "mask_id": "mask_object_01",
  "pose_base": {
    "x": 0.421,
    "y": 0.184,
    "z": 0.733
  },
  "pose_valid": true,
  "graspable": true,
  "destination": "lost_found_bin",
  "status": "detected"
}
```

| 필드 묶음 | 생성 주체 | 용도 |
| --- | --- | --- |
| `semantic_label`, `task_category` | ER 2 | 객체 의미와 처리 방향 |
| `mask_id`, `pose_base`, `pose_valid` | Local Perception | 위치·형상 계측 |
| `graspable` | Grasp·Motion | 실행 가능성 판단 |
| `destination` | ER 2와 정책 검증 | 작업 목적지 |
| `status` | Edge Orchestrator | 처리 진행 결과 연결 |

재스캔 시에는 bbox IoU, mask IoU, 3D 중심점 거리와 semantic label을 조합해 기존
`object_id`와 새 관찰을 연결한다.

## 5. 결정과 실행의 결합

ER 2의 의미 판단과 로컬 시스템의 실행 가능성은 서로 다른 결과다.

| 판단 | 담당 |
| --- | --- |
| 객체가 무엇인지 | ER 2 |
| 어떤 category와 목적지에 해당하는지 | ER 2와 작업 정책 |
| 현재 위치가 유효한지 | Local Perception |
| 파지 가능한지 | Grasp·Motion |
| 실행할 trajectory가 존재하는지 | Grasp·Motion |
| 요청과 실행 결과가 같은 객체에 연결되는지 | Edge Orchestrator |

```text
ER 2의 객체·목적지 결정
        +
로컬의 pose·grasp·trajectory 결과
        ↓
Edge Orchestrator가 동일 object ID로 결합
        ↓
로봇 실행
```

ER 2의 분류 결과만으로 로봇을 실행하지 않고, 로컬 계산 결과가 준비된 경우에만 같은
객체의 작업 요청과 결합한다.

## 6. 실행 결과 피드백

```text
장면 관찰
→ ER 2 의미 판단·다음 작업 결정
→ 로컬 객체 위치·파지·경로 계산
→ 로봇 실행
→ 실행 결과와 최신 장면 기록
→ ER 2 재판단
```

ER 2에 반환할 실행 결과에는 최소한 다음 정보가 필요하다.

```json
{
  "object_id": "object_01",
  "requested_action": "move",
  "result": "success",
  "destination": "lost_found_bin",
  "observation_changed": true,
  "remaining_object_count": 3
}
```

실패한 경우에는 실패 단계, 원인 코드, 객체의 최신 위치와 재관찰 필요 여부를 함께
전달한다.

## 7. 로깅 경계

동일한 `task_id`, `scene_id`, `object_id`, `request_id`로 다음 정보를 연결한다.

- ER 2에 전달한 이미지·상태·정책 버전
- ER 2의 구조화 출력
- schema·정책 검증 결과
- mask, Depth 품질, pose와 grasp 후보
- 선택한 trajectory ID와 로봇 실행 결과
- 실행 전후 관찰과 최종 작업 결과
