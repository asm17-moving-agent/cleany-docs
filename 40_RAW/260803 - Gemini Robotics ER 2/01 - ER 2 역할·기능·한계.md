## 모델 구분

| 모델 | 종류 | 주 역할 | 배포 상태 |
|---|---|---|---|
| Gemini Robotics ER 2 | VLM | 장면 이해, 장기 계획, tool·VLA orchestration | Gemini API·AI Studio |
| Gemini Robotics 2 | VLA | 영상·언어를 motor action으로 연결 | Early-access partner |
| Gemini Robotics On-Device 2 | VLA | 로봇 장치에서 저지연 motor action 생성 | Early-access partner |

ER 2는 VLA가 아니다. 물체와 공간을 이해하고 다음 고수준 행동을 선택하지만 실제
관절 명령은 연결된 VLA, motion planner 또는 로봇 API가 만든다.

## 입출력과 기능

- 입력: text, image, video, audio
- 출력: text, structured result, function call
- 공간 추론: point, bounding box, 관계와 trajectory 후보
- Task orchestration: 여러 tool을 순서대로 호출하는 장기 작업
- Video understanding: 진행도 분류, 성공 탐지, 중요 시점 탐색
- Streaming: 연속 입력과 저지연 function calling

일반 endpoint는 `gemini-robotics-er-2-preview`, 스트리밍 endpoint는
`gemini-robotics-er-2-streaming-preview`다. Preview API와 SDK 계약은 변경될 수 있다.

## Cleany에 적합한 역할

- 여러 물체가 있는 책상 장면의 의미 해석
- 쓰레기·분실물 후보와 불확실한 물체의 구분 제안
- 처리 가능한 물체의 작업 순서 제안
- 허용된 Capability 또는 VLA-backed Manipulation Skill 선택
- 실행 결과와 최신 관찰을 바탕으로 다음 행동·완료 여부 판단
- 불가능하거나 불확실한 작업을 중단·보류하고 결과로 표현

## 책임 범위 밖

- 최종 base 기준 3D 좌표와 frame transform 확정
- grasp pose, gripper 폭·힘과 접촉점 계산
- 충돌 없는 관절 trajectory와 고주기 servo 제어
- 속도·가속도·관절·작업공간 제한의 최종 강제
- safe stop과 물리적 e-stop의 유일한 판단
- Mission Manager의 상태 직접 변경

## 한계와 도입 조건

ER 2는 Preview 상태의 확률적 클라우드 모델이다. 환각, 누락, 잘못된 좌표·tool 인자,
네트워크 지연과 서비스 실패가 발생할 수 있다. Cleany에서는 다음을 로컬에서
검증·강제해야 한다.

- tool allowlist와 argument schema
- 현재 Mission 상태에서 허용된 행동인지 확인
- 객체·목적지 ID와 좌표 유효성
- 작업공간·관절 한계·충돌 검사
- watchdog, timeout과 실행 취소
- safe stop과 물리적 e-stop

실제 채택은 Cleany 장면에서 정확도, 지연, 실패 형태, 비용과 개인정보 조건을
측정한 뒤 결정한다.
