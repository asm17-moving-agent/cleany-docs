# 261002 - Action 결과와 관찰 자료 전달 정책 합의

## 논의 맥락과 출처

2026-10-02 KB 변경사항 검토 대화에서 Manipulation 결과의 구분과 관찰 자료의
저장 및 전송 정책을 다시 설명하고 추천했다. 사용자는 다음 순서로 요청했다.

- 분실물 처리 범위의 불일치는 일단 보류하고, 놓기 성공 기준은 구현 레포 `main`을
  기준으로 검토하도록 요청했다.
- Action 결과와 사진 정책을 어떻게 정할지 추천을 요청했다.
- 아래 추천안을 제시한 뒤 사용자가 "그렇게 진행해줘"라고 반영을 요청했다.

이 기록은 해당 대화에서 확인한 선택과 미결정 범위를 보존한다. 구현 완료 사실이나
GitHub PR 검토 이력을 대신하지 않는다. 앞선 검토의 배경은
[책상 정리 작업 흐름 논의](<260930 - Table Cleanup Workflow.md>)에 남아 있다.

## Action 결과에 관한 선택

작업 중인 Action 설계의 다음 결과 구분을 유지한다. KB에는 결과의 의미와 후속
처리 원칙을 기록하고, 정확한 필드와 상태 이름은 구현 명세에서 관리한다.

| 추천안의 결과 | 의미 | 후속 처리 |
|---|---|---|
| `SUCCESS` | 행동의 성공 조건 충족 | 기록하고 재관찰 |
| `BLOCKED` | 실행 전 조건 미충족 | 이유를 기록하고 다른 행동 검토 |
| `FAILED` | 실행 중 실패 | 정지를 확인하고 재관찰 |
| `CANCELED` | 취소 후 정지 확인 | 진행 기록을 보존하고 종료 |
| `FATAL` | 치명 오류 또는 정지 확인 불가 | 후속 동작 차단과 사람 확인 |

성공 여부만 반환하지 않고 실패 이유, 정지 확인, 물체 보유 상태와 놓기 검증 상태를
함께 보존한다. ROS 종료 상태와 행동 결과를 함께 판단한다. 집기 실패 뒤 안전하게
멈춘 경우와 정지를 확인하지 못한 경우는 후속 처리가 다르다는 점이 추천 이유였다.

이 결과 경계는 반영할 목표이며 구현 레포 `main`에 수거 Action과 놓기 판정이 이미
구현됐다는 뜻은 아니다. 놓기 동작 완료만으로 성공을 판정하는 문구는 앞선 `main`
기준 검토에서 삭제했다. 구체적인 놓기 성공 판정 방식은 이 선택에서 새로 정하지 않는다.

## 관찰 자료에 관한 선택

- Backend에는 작업 전 사진과 최종 사진 및 해당 관찰의 인식 정보를 전송한다.
- 첫 조작 전에 작업 전 사진과 인식 정보를 로컬에 저장한다. 로컬 저장에 실패하면
  첫 조작을 시작하지 않는다.
- 로컬 저장에 성공하면 Backend 저장 확인을 기다리지 않고 조작을 진행한다.
- 사진 전송은 제한된 자동 재시도와 운영자의 수동 재전송을 지원한다. 재전송은 같은
  관찰 ID를 사용해 Backend의 중복 저장을 막는다.
- Backend 저장이 확인되면 로컬 사본을 삭제할 수 있다.
- 미전송 자료의 보관 기한은 별도로 정한다. 기한에 따라 자료를 삭제하더라도 미전송
  사실과 사유는 기록에 남긴다.

작업 증거를 로컬에 확보하면서 사진 전송 지연이 조작 전체를 막지 않도록 한다는 것이
추천 이유였다. 전송 자동 재시도와 물체 조작의 재실행은 구분한다.

## 아직 정하지 않은 조건

- 자동 재시도의 한도와 간격 및 재연결 시 전송 방식
- 미전송 로컬 자료의 보관 기한과 기한 계산 및 삭제 조건. 기존 초안의 7일은 검토값이다.
- Backend 저장 확인, 수동 재전송과 중복 판별의 구체적인 ROS/API 계약
- Action 결과를 ModuleResult와 MissionReport에 연결하는 구체적인 adapter 규칙

분실물 처리 범위의 불일치는 이번 반영에서 보류한다. Backend에 저장된 자료의
보관 기간, 접근 권한과 삭제 기준도 이번 로컬 사본 정책으로 확정하지 않는다.
