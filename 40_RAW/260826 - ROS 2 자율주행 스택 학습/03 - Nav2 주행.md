# 260826 - Nav2 주행

## 1. 학습 목표

유효한 지도와 현재 pose가 주어진 뒤 Nav2가 목표 pose까지의 path를 만들고, 장애물을
반영하면서 차체 속도 명령을 생성하고, 성공 또는 실패 결과를 반환하는 흐름을
이해한다.

## 2. 큰 흐름

```text
NavigateToPose goal
  → Behavior Tree가 실행 단계 선택
  → Planner가 Global costmap에서 path 생성
  → 필요하면 Smoother가 path 보정
  → Controller가 Local costmap을 보며 path 추종
  → cmd_vel 출력
  → Goal checker와 Progress checker가 도착 또는 정체 판정
  → 재계획, Recovery, 성공, 실패 또는 취소
```

## 3. 환경 표현, 계획과 제어

### 3.1 Costmap

| 구분 | 주된 범위 | 주된 소비자 | 확인할 내용 |
|---|---|---|---|
| Global costmap | 지도 전체 또는 넓은 계획 범위 | Planner | Static map, 장애물과 inflation |
| Local costmap | Robot 주변의 짧은 시간 범위 | Controller와 Recovery | 실시간 장애물, footprint와 갱신 주기 |

학습할 layer:

- Static layer가 저장된 지도를 어떻게 반영하는가
- Obstacle 또는 Voxel layer가 sensor 관측을 어떻게 반영하고 지우는가
- Inflation layer와 robot footprint가 안전 여유에 어떤 영향을 주는가

### 3.2 Planner와 Controller

| 역할 | 입력 | 출력 | 학습 기록 |
|---|---|---|---|
| Planner | 현재 pose, 목표 pose와 Global costmap | Path | 작성 예정 |
| Smoother | 기존 path와 환경 표현 | 보정된 path | 작성 예정 |
| Controller | Path, Local costmap과 현재 velocity | `cmd_vel` | 작성 예정 |
| Goal checker | 현재 pose와 목표 조건 | 도착 판정 | 작성 예정 |
| Progress checker | 시간에 따른 이동 상태 | 정체 판정 | 작성 예정 |

Cleany는 4륜 Mecanum base이므로 후보가 `linear.y`를 포함한 holonomic motion을
어떻게 처리하는지 확인한다. 이를 이유로 특정 Planner나 Controller를 미리 선택하지
않는다.

## 4. 실행 조정, 복구와 안전

Behavior Tree는 계획, 추종과 복구의 실행 순서를 조정한다. Lifecycle node는 서버의
구성과 활성화 순서를 관리한다. 이 두 책임을 motor-level safe stop이나 물리 e-stop과
같은 것으로 해석하지 않는다.

확인할 항목:

- 경로 생성 실패와 경로 추종 실패를 어떻게 구분하는가
- 장애물 때문에 기다리는 경우와 Localization이 무너진 경우를 어떻게 구분하는가
- 재계획, Costmap clear와 후진 같은 Recovery를 언제 허용하는가
- Cancel과 timeout이 마지막 속도 명령을 남기지 않는가
- Navigation 결과가 상위 Mission 결과로 어떻게 전달되는가

## 5. 검증 기록

| 단계 | 최소 확인 증거 | 결과 |
|---|---|---|
| Costmap | Map, sensor layer와 footprint 시각화 | 작성 예정 |
| Planner | 시작과 목표를 잇는 유효 path | 작성 예정 |
| Controller | Path 추종 중 `cmd_vel`과 pose 변화 | 작성 예정 |
| 장애물 | 재계획 또는 안전한 정지 | 작성 예정 |
| Goal | 도착 pose 오차와 result | 작성 예정 |
| Cancel과 실패 | 정지, failure code와 복구 경계 | 작성 예정 |

## 7. 주의점

- Path가 생성됐다는 사실만으로 안전한 주행 또는 도착을 증명하지 않는다.
- 기본 파라미터와 demo world의 성공을 실제 Mecanum base의 성능으로 일반화하지 않는다.
- Recovery 횟수를 늘려 sensor, TF와 Odometry 문제를 가리지 않는다.
