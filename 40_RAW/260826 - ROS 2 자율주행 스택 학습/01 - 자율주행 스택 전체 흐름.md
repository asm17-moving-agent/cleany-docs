# 260826 - 자율주행 스택 전체 흐름

## 1. 학습 목표

자율주행을 하나의 알고리즘이 아니라 센서 입력, 상태 추정, 환경 표현, 경로 계획,
제어와 구동이 반복되는 폐루프로 이해한다. 각 계층이 무엇을 입력받고 무엇을
출력하며, 어느 좌표계와 시간을 사용하는지 설명할 수 있는 상태를 목표로 한다.

## 2. 큰 흐름

```text
Cleany Mission Manager
  → 목표 pose와 Navigation 요청
  → Nav2 실행 조정
  → Global costmap 기반 경로 계획
  → Local costmap 기반 경로 추종과 장애물 회피
  → cmd_vel
  → 모바일 베이스와 motor controller
  → wheel encoder, IMU와 LiDAR
      ├─ Odometry와 상태 추정 → odom → base_link
      ├─ SLAM 또는 Localization → map → odom
      └─ 장애물 관측 → Global, Local costmap
  → 갱신된 위치와 환경으로 다음 제어 주기 반복
```

Navigation 성공은 이 폐루프가 목표 pose의 도착 조건을 만족하고 결과를 상위
Mission에 반환한 상태다. 지도 작성만 성공하거나 `cmd_vel`이 발행된 것만으로 전체
Navigation 성공이라고 판단하지 않는다.

## 3. 계층별 책임

| 계층 | 입력 | 출력 | 학습할 핵심 |
|---|---|---|---|
| Mission 경계 | 좌석 ID 또는 목표 pose | Navigation 요청과 결과 | 목표 생성, 취소와 도착 의미 |
| 로봇과 센서 | 속도 명령과 실제 환경 | Encoder, IMU, LiDAR | 운동학, 장착 위치, 시간과 오차 |
| Odometry와 상태 추정 | Encoder, IMU | 연속적인 local pose와 velocity | Drift, covariance와 sensor fusion |
| SLAM 또는 Localization | Scan, Odometry와 기존 지도 | 지도, 전역 pose 관계 | Mapping과 운영 위치 추정의 차이 |
| Costmap | 지도, sensor와 footprint | 주행 가능한 환경 표현 | 정적 장애물, 동적 장애물과 여유 거리 |
| Planner | 현재 pose, 목표 pose와 Global costmap | 전역 path | 경로 유효성과 최적화 기준 |
| Controller | Path, Local costmap과 현재 속도 | 차체 속도 명령 | 경로 추종, 장애물 회피와 도착 판정 |
| 실행 조정과 안전 | 각 서버의 feedback과 실패 | 재계획, 복구, 취소 또는 종료 | Behavior Tree, lifecycle과 safe stop |

## 4. 좌표계와 데이터 소유권

기본 frame tree는 다음과 같이 읽는다.

```text
map
└── odom
    └── base_link
        ├── laser
        └── imu_link
```

| Transform | 일반적인 역할 | Cleany에서 확인할 소유자 |
|---|---|---|
| `map → odom` | 전역 지도에서 누적 Odometry 오차 보정 | SLAM 또는 Localization |
| `odom → base_link` | 짧은 시간에 연속적인 차체 이동 추정 | 활성 Sim 또는 Real Odometry backend |
| `base_link → sensor` | 차체에 장착된 센서의 고정 위치와 방향 | Robot description 또는 sensor publisher |

한 transform을 두 node가 동시에 발행하지 않아야 하며, message timestamp와 TF가
맞지 않으면 각 알고리즘이 정상이어도 전체 흐름이 끊길 수 있다.

## 5. 먼저 이해할 항목

- [ ] 목표 pose가 어떤 frame과 의미로 주어지는지 설명한다.
- [ ] `map`, `odom`, `base_link`의 차이와 transform 소유자를 설명한다.
- [ ] Encoder, IMU와 LiDAR가 각각 어느 계층에 사용되는지 설명한다.
- [ ] SLAM, Localization과 Costmap이 서로 다른 책임임을 설명한다.
- [ ] Planner의 path가 Controller의 속도 명령으로 바뀌는 과정을 설명한다.
- [ ] 성공, 재계획, 복구, 취소와 safe stop의 차이를 설명한다.
