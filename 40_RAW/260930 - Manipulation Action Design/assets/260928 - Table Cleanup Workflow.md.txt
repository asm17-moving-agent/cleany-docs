# 책상 정리 작업 흐름과 책임 경계 논의

## 1. 요약

이 문서는 대화에서 정리한 책상 작업 흐름과 추가 요구를 보존하는 **Raw 논의
기록**이다. 사람 검토를 마친 결정이나 구현 완료 사실로 취급하지 않는다.

로봇이 지정 책상에 도착한 뒤 관측과 정리를 어떻게 이어갈지 설명하는
**책상 작업 경계 후보**다. Mission Manager가 책상까지 이동한 후 책상 작업을
한 번 요청하면, 작업 담당자가 스캔·처리·재스캔을 반복하고 결과를 돌려주는
구조를 제안한다. 기존 Mission Manager FSM 문서의 직접 모듈 호출 구조를
대체하기로 확정한 Decision은 아직 없다.

핵심은 **작업 순서를 맡는 곳**과 **기능을 구현하는 곳**을 구분하는 것이다.
책상 작업 담당자가 Perception에 스캔을 요청하더라도 Perception은 독립된
기능이다. 다른 점검 작업도 Perception을 사용할 수 있다.

## 2. 기획 맥락

운영자가 좌석 정리를 요청하면 로봇은 해당 책상으로 이동하고, 남은 물체를
관찰한 뒤 안전하게 처리할 수 있는 대상만 옮겨야 한다. 불확실하거나 위험한
물체는 건드리지 않고 사람 확인 대상으로 남긴다. 책상 전체의 진행과 최종
결과는 운영자에게 전달되어야 한다. 작업 시작 시 책상 사진과 물체별 위치·라벨·
분류 결과를 상위단에 보내, 상위단이 사진 위에 물체 정보를 표시한다는 추가
요구가 있다.

책상에 도착하기 전에는 어떤 물체가 있는지 알 수 없다. 따라서 책상 작업의
첫 단계는 **책상 전체 관측**이다. 물체를 하나 옮기면 장면이 달라지므로
다음 물체를 정하기 전에 다시 관측해야 한다.

## 3. 기술 개념

### 3.1 책상 도착 후 흐름

```mermaid
flowchart LR
    M["Mission Manager<br/>책상까지 이동"] --> T["책상 작업<br/>한 번 요청"]
    T --> P["Perception<br/>책상 관측"]
    P --> D["Planner·정책<br/>전체 물체 분류·다음 대상 판단"]
    D --> I["첫 관측 이미지·물체 정보<br/>상위단 전달"]
    I -->|"안전하게 처리할 대상"| X["매니퓰레이션<br/>물체 이동"]
    X --> P
    I -->|"더 처리할 대상 없음"| R["남은 물체·검증 결과 정리"]
    R --> M
```

1. **이동:** Mission Manager가 지정 책상 도착을 확인한다.
2. **관측:** 책상 작업 담당자가 Perception에 현재 책상 상태를 요청한다.
3. **판단:** Planner·정책이 첫 관측의 물체별 라벨·분류·보류 여부를 확인하고
   처리할 대상과 순서를 제안한다. Mission Manager가 물체의 의미를 직접 판단하지
   않는다.
4. **초기 관측 전달:** 첫 물체를 집기 전에 같은 장면의 원본 이미지와 물체별
   이미지 내 위치·라벨·분류 결과를 상위단에 전달한다. 상위단이 overlay
   이미지를 만든다. 불확실한 물체는 확정 분류로 꾸미지 않고 사람 확인 대상으로
   표시한다.
5. **실행:** 책상 작업 담당자가 선택된 물체의 집기·운반·놓기를 진행한다.
6. **재관측:** 한 물체를 처리한 뒤 새 장면을 관측하고 다음 판단을 요청한다.
7. **보고:** 더 처리할 수 있는 대상이 없으면 처리·미처리·사람 확인·미검증
   항목을 모아 Mission Manager에 반환한다.

책상 작업 담당자는 이 반복 순서를 책임진다. Perception의 물체 탐지 방식이나
Planner의 분류 정책을 내부에 복사하지 않는다. Mission Manager는 책상 내부의
물체별 단계를 하나씩 지휘하지 않고, 책상 작업의 시작·취소·종료를 다룬다.

### 3.2 첫 관측을 운영자에게 보여주는 이유

운영자는 로봇이 작업을 시작할 때 책상에서 무엇을 보았고 어떻게 분류했는지
확인할 수 있어야 한다. 상위단이 이미지를 그릴 수 있도록 로봇은 이미지와
그 이미지에 대응하는 물체 위치·라벨·분류를 함께 전달해야 한다. 이후 재관측의
운영자 표시 범위와 전송 빈도는 아직 정하지 않았다.

### 3.3 Perception을 독립적으로 두는 이유

Perception은 요청 시점의 장면을 관측하는 공통 기능이다. 책상 정리뿐 아니라
조작 없는 현장 점검이나 작업 전후 비교에서도 사용할 수 있다. 특정 책상
작업의 순서를 Perception이 결정하거나, 매니퓰레이션 코드를 알아야 할
필요는 없다.

반대로 책상 작업 담당자가 Perception에 관측을 요청한다고 해서 Perception이
그 담당자 안에 속하는 것은 아니다. **호출 관계와 소유 관계를 구분한다.**

### 3.4 완료를 판단할 때

물체가 화면에서 사라졌다는 이유만으로 성공이라고 판단하지 않는다. 가림,
시야 이탈, 관측 실패가 있을 수 있다. 유효한 새 관측과 물체별 처리 기록을
함께 확인한다. 사람이 확인해야 할 물체나 놓기 결과를 확인하지 못한 물체는
남은 사실 그대로 보고한다. 재확인 횟수와 세부 결과 표현은 구현 계약에서
정하고, 사람 검토 전에는 제품 정책으로 확정하지 않는다.

## 4. 인터페이스 / 경계

| 구성요소 | 책임 | 경계 |
|---|---|---|
| Mission Manager | 이동, 책상 작업 요청, 미션 상태와 최종 보고 | 물체별 스캔·집기 순서를 직접 수행하지 않음 |
| 책상 작업 담당자 | 관측·판단·실행 기능을 호출해 책상 작업 순서를 조정 | 물체 탐지와 의미 분류 알고리즘을 복제하지 않음 |
| Perception | 요청받은 시점의 물체·공간 관측 제공 | 조작 여부와 작업 순서를 결정하지 않음 |
| Planner·정책 | 처리 가능 여부·다음 대상·보류 이유 판단 | 팔 관절 동작을 계획하지 않음 |
| 매니퓰레이션 실행 | 지정된 물체를 집어 옮기고 결과를 제공 | 분류 의미나 미션 상태를 결정하지 않음 |
| 상위단 | 첫 관측 이미지와 물체 정보를 받아 표시 | 로봇의 물체 선택이나 미션 상태를 변경하지 않음 |

Mission Manager만 미션 상태를 전이한다. 책상 작업 담당자의 내부 진행은
미션 상태와 구분한다. 결과가 부분 완료이거나 물체를 든 채 중단된 경우의
복귀·사람 인계 판단은 안전 정책 검토가 필요하다.

## 5. 가정

- 책상 도착 여부를 Mission Manager가 알 수 있고, 관측할 작업 영역을 구분할
  수 있다고 가정한다. 정확한 영역 지정 방식은 아직 정해지지 않았다.
- Perception과 Planner는 책상 작업 외에도 독립적으로 호출 가능한 기능으로 둔다.
- 작업 중 새 관측이 실패하면 책상이 비었다고 단정하지 않는다.
- 첫 관측 이미지와 물체 정보는 같은 촬영 장면에 대응해야 한다.
- 분실물 후보의 자동 이송 허용 여부는 아직 검토 중이다. 합의 전에는 자동
  조작 대상으로 확정하지 않는다.

## 6. 리스크

- 서로 다른 시점의 물체 번호를 같은 물체로 오인하면 중복 집기나 누락이 생길
  수 있다.
- 관측 실패를 빈 책상으로 해석하거나 놓기 명령만으로 안착을 확정하면 잘못된
  완료 보고가 생긴다.
- 이미지와 물체 위치가 서로 다른 시점의 것이면 상위단 overlay가 실제 책상과
  다르게 보일 수 있다.
- 책상 작업 담당자가 인지·분류 구현까지 소유하면 Perception의 재사용성과
  책임 경계가 흐려진다.
- 기존 Mission Manager FSM 초안은 Perception·Planner·Skill Executor를 직접
  순서대로 호출한다. 책상 작업 담당자에게 반복 순서를 맡기는 안을 채택하려면
  해당 FSM의 호출 경계와 보고 방식을 함께 검토해야 한다.

## 7. 관련 결정

책상 작업의 오케스트레이션 소유권을 확정한 selected Decision은 아직 없다.
기존 Mission Manager FSM과 ROS 2 소프트웨어 아키텍처 초안은 직접 모듈
호출을 설명한다. 이 기록은 책상 작업에 한정한 **대안 논의**이며 사람 검토와
Decision 없이 기존 문서를 대체하지 않는다. 이미지 전달 방식, 상위단의
저장·표시 계약과 재관측 표시 범위도 아직 미정이다.
