# 260930 - 책상 작업 반복을 Mission Manager FSM 루프로 처리

> **이전 비교안.** 이후 대화에서 전체 미션과 책상 Action의 경계를 다시 검토했다.
> 현재 KB 정렬 기준은 [[30_DECISIONS/Technical/260930 - 전체 미션과 책상 정리 Action의 책임 경계 분리|후속 책임 경계 초안]]이다.
> 이 문서는 과거 논의를 보존하는 `draft`이며 채택된 결정이나 현재 구현 계약이 아니다.
> 아래 이유와 사용자 선택 설명은 당시 논의 기준이다.

## 1. 결정

책상 도착 뒤의 스캔·판단·조작·재스캔 반복을 **Mission Manager FSM의 사이클**로
처리하는 Technical Decision 초안이다. 사람 검토 전이므로 아직 확정 결정이 아니다.

- 처리 대상 하나를 실행한 뒤 `EXECUTE_TASKS`에서 `PERCEIVE`로 돌아가 새로 관측하고
  새 plan을 받는다.
- Planner가 실행할 task가 없다고 판단한 유효 스캔을 설정된 횟수만큼 확인하면
  `RETURN_HOME`으로 전이한다.
- 첫 사이클의 plan을 받은 뒤, 물체를 움직이기 전에 별도 FSM 상태에서 첫 관측
  결과(원본 이미지, bbox, 최종 분류) 전달 port를 호출한다.
- Perception, Planner, Skill Executor의 기존 책임 경계는 유지한다.

## 2. 이유

- 물체 하나를 옮기면 장면이 달라지므로 다음 판단 전에 다시 관측해야 한다는 요구가
  Raw 논의에 있다.
- 기존 FSM은 한 번의 관측으로 전체 skill sequence를 실행해, 처리 중 달라진 장면과
  남은 물체를 다시 판단하지 못한다.
- 첫 관측의 물체 번호로 이후 skill을 지정하면 Perception snapshot 만료 뒤 대상을
  찾지 못하고, 관측 사이의 동일 물체 연결 기준도 없다.
- FSM 루프는 상태 전이 권한을 Mission Manager에만 두는 기존 원칙과 모듈 경계를
  바꾸지 않고 재관측을 보장한다.
- 첫 물체를 움직이기 전에 첫 관측을 전달한다는 순서는 상태 전이를 소유한
  Mission Manager만 보장할 수 있다.

## 3. 대안

| 대안 | 선택하지 않은 이유 |
|---|---|
| FSM은 그대로 두고 `pick_object` 안에서 대상을 다시 관측한다 | snapshot 만료와 동일 물체 연결 문제가 남고, 새로 드러나거나 밀린 물체를 Planner가 다시 판단하지 못한다. 최종 빈 책상 확인 위치도 없다. |
| 책상 작업 담당자에게 한 번 요청하고 내부 반복을 맡긴다 | Mission Manager FSM의 `PERCEIVE`·`PLAN_TASKS`·`EXECUTE_TASKS` 호출 경계와 보고 방식을 함께 바꿔야 한다. 사용자는 FSM 루프 안을 선택했다. 이 대안의 최종 폐기 여부는 검토 필요다. |
| Perception 또는 Planner가 첫 관측을 직접 전달한다 | Perception에는 최종 분류가 없다. Planner는 계획 책임에 외부 전달과 미션 문맥이 섞인다. |

## 4. 가정

- Planner는 매 사이클 새 관측을 입력으로 받아 처리 순서와 `collect`·`skip`·
  `human_review` 판단을 다시 만든다.
- Mission Manager는 한 사이클에서 plan의 첫 실행 task 하나만 실행한다.
- 첫 관측 전달 port의 성공은 로컬 발행까지를 뜻하며 Backend 저장 확인을 뜻하지 않는다.
- 종료 확인 횟수와 최대 사이클 수는 설정값이며 기본값은 추가 정의가 필요하다.

## 5. 리스크

- 물체마다 관측과 계획을 반복하므로 책상 하나의 처리 시간이 늘어난다.
- Mission Manager가 책상 안의 반복을 지휘하므로 사이클 카운터, 재시도 범위,
  기록 누적 규칙이 FSM에 추가된다.
- 사이클 상한, 사라진 처리 대상, 첫 관측 전달 실패의 결과 표현이 정해지지 않으면
  잘못된 완료 보고가 생길 수 있다.

## 6. 재검토 조건

- 사이클당 관측·계획 시간이 운영 목표를 넘는다.
- 책상 외 작업 영역에서 다른 반복 구조가 필요해진다.
- 첫 관측 전달 계약에서 Backend 저장 확인을 첫 조작 조건으로 요구한다.
