# 260722 - 객체 탐지·세그멘테이션 클래스 정의 및 라벨링 가이드라인

## 1. 요약

이 문서는 객체 탐지·인스턴스 세그멘테이션 데이터의 라벨링을 시작하기 전에 탐지 대상 클래스, annotation schema와 작업 기준을 합의하기 위한 초안이다.

클래스별 포함·제외 조건, Bounding Box·Polygon 작성 방식, 모호한 경계와 예외 사례, 검수 기준을 기록한다. 현재 모든 항목은 사람 검토가 필요한 Raw 작업 문서 틀이며, 이 문서만으로 클래스나 라벨링 정책이 확정된 것은 아니다.

## 2. 기획 맥락

`YOLO11n-seg`를 우선 선정안으로 검토하면서 박스와 인스턴스 마스크를 함께 제공하는 학습·평가 데이터가 필요해졌다. 기본 COCO-Seg 클래스에 없는 끌리니 대상은 별도 데이터를 수집하고 라벨링해야 하며, COCO에 포함된 클래스도 실제 운영 환경의 물체 범위와 처리 목적에 맞게 정의를 다시 확인해야 한다.

이 문서는 객체 탐지·세그멘테이션 모델 비교 조사의 후속 작업을 기록한다. 검토가 완료된 내용은 [[20_TECHNICAL/07 - Data and Evaluation|Data and Evaluation]] 또는 별도 Technical 문서에 반영하며, 최소 데이터셋 범위와 라벨 기준에 관한 미해결 질문은 [[20_TECHNICAL/99 - Questions|Technical Questions]]에서 관리한다.

4장의 클래스 후보 목록은 무인 스터디카페 책상 정리 시나리오를 근거로 AI와의 대화에서 정리한 초안이다. 클래스는 물체 식별을 기준으로 정의하며, 쓰레기·분실물·기타 처리 대상 여부는 정리를 위한 참고 그룹으로만 사용하고 최종 처리 판정은 클래스 라벨만으로 확정하지 않는다. 실제 현장 촬영 데이터나 팀 검토를 거치지 않았으므로 클래스 이름, 포함 범위, 개수 모두 확정값이 아니다.

## 4. 클래스 정의

### 4.1 클래스 선정 원칙

- 클래스는 물체 식별을 기준으로 정의한다. 4.2의 쓰레기 후보·분실물 후보·기타 집기류 구분과 처리 목적은 정리를 위한 참고 그룹이며, 최종 처리 판정은 클래스 라벨만으로 확정하지 않는다.
- 외형만으로 안정적으로 구분할 수 없는 개념은 단일 이미지 라벨로 확정하지 않는다.
- 클래스 사이의 포함 관계와 상호 배타 여부를 명시한다.
- 클래스 추가·병합·폐기 시 기존 dataset과 model label index에 미치는 영향을 기록한다.

### 4.2 클래스 목록

Class ID는 아직 표에 포함하지 않는다. 학습에 사용하는 ID가 정해지면 영문 라벨을 기준으로 0부터 시작하는 연속 정수인지, background를 별도 class로 두는지와 함께 추가한다.

아래 표는 [[10_PLANNING/02 - Target Scenario|Target Scenario]]의 쓰레기 후보·분실물 후보·기타 물체 구분을 참고해 3개 하위 절로 나눴다. 다만 `cup`처럼 하나의 클래스가 쓰레기(일회용 종이컵)와 개인 소지품(재사용 텀블러)에 걸쳐 있는 경우가 있어 그룹 배정은 잠정적이며, 실제 처리 판정은 클래스 라벨만으로 확정하지 않는다. COCO-Seg 80종에 포함된 `cup`, `bottle`, `book`도 무인 스터디카페 실물(종이컵, 텀블러, 프린트물)과 형태 분포가 달라 재학습이 필요할 수 있다는 점을 각 클래스의 제외·혼동 기준에 표시했다.

| receipt       | 감열지 재질 영수증             | 플라스틱 카드류                   | card                         | 검토 필요     |

### 4.4 속성·보조 표기

| 속성               | 허용값            | 적용 대상                   | 사용 목적             | 필수 여부             | 상태  |
| ---------------- | -------------- | ----------------------- | ----------------- | ----------------- | --- |
| 가림(occluded)     | `true`/`false` | 모든 인스턴스(Box·Polygon 공통) | 가시 영역과 평가 조건 구분   | 권장(필수 아님)         | 결정  |
| 화면 잘림(truncated) | `true`/`false` | 모든 인스턴스                 | 이미지 경계 밖 물체 구분    | 권장(필수 아님)         | 결정  |
| 판독 곤란(difficult) | `true`/`false` | 모든 인스턴스                 | 사람 간 판단 불일치 후보 표시 | 권장(필수 아님)         | 결정  |
| 무시(ignore)       | `true`/`false` | 영역(region) 단위           | 학습·평가 제외 영역 표시    | 조건부(해당 영역이 있을 때만) | 결정  |

## 5. Annotation schema

### 5.1 Annotation 유형

| 유형             | 적용 대상          | 필수 여부                                               | 작성 단위                       | 저장 형식                                   | 상태    |
| -------------- | -------------- | --------------------------------------------------- | --------------------------- | --------------------------------------- | ----- |
| Bounding Box   | 탐지 대상 인스턴스     | 조건부(Polygon에서 자동 계산, `YOLO11n-seg` 학습 시 별도 라벨링 불필요) | 인스턴스별 1개                    | Polygon에서 자동 파생                         | 결정    |
| Polygon / Mask | 세그멘테이션 대상 인스턴스 | 필수                                                  | 인스턴스별 1개 이상(분리된 영역·구멍 포함 시) | 정규화 polygon 좌표(Ultralytics YOLO-seg 포맷) | 결정    |
| Ignore Region  | 판독 불가·평가 제외 영역 | 조건부(해당 영역이 있을 때만)                                   | 영역별                         | 도구별 지원 확인 필요                            | 검토 필요 |
| Image-level 속성 | 촬영 조건·빈 이미지 등  | 선택                                                  | 이미지별                        | 검토 필요                                   | 검토 필요 |

### 5.2 공통 schema 필드

| 필드 | 형식·허용값 | 필수 여부 | 설명 | 예시 |
|---|---|---|---|---|
| `image_id` | 이미지 파일명(확장자 제외) 또는 상대 경로 | 필수 | 이미지 고유 식별자 | `desk_0001` |
| `instance_id` | annotation 파일 내 줄 번호(0부터 시작) | 필수 | 이미지 안 인스턴스 식별자 | `0`, `1`, `2` |
| `class_id` | 4.2의 확정 ID(정수, 0부터 시작) | 필수 | 대상 클래스 | Class ID 확정 후 채움 |
| `bbox` | 해당 없음(Polygon에서 자동 계산) | 해당 없음 | Bounding Box 좌표 | Ultralytics YOLO-seg는 별도 저장하지 않음 |
| `segmentation` | 정규화된 `(x, y)` polygon 좌표 목록, 0~1 범위, 원점은 이미지 좌상단 | 필수 | 인스턴스 외곽 영역 | `x1 y1 x2 y2 ...` |
| `attributes` | 4.4의 허용값 | 선택 | 가림·잘림 등 보조 정보 | 도구별 저장 방식은 검토 필요 |

좌표는 `YOLO11n-seg` 학습 입력 기준을 따른다. 원점은 이미지 좌상단, x는 오른쪽·y는 아래쪽 방향, 값은 0~1로 정규화한다. Polygon은 물체 외곽을 따라가는 점 순서로 저장하며 winding 방향은 강제하지 않고 시작점을 반복해 닫지 않는다. 반올림 자릿수는 annotation 도구 선택 후 확정한다.

## 6. 라벨링 작업 기준

### 6.1 공통 기준

- 이미지에 존재하는 모든 대상 인스턴스를 빠짐없이 표시한다(누락 금지). 특정 클래스만 선택적으로 라벨링하지 않는다.
- 클래스 판단은 물체의 외형을 우선 기준으로 하고, 외형만으로 판단하기 어려우면 용도·배치 상태를 보조 근거로 사용한다(4.1 원칙과 일치).
- 확신할 수 없는 물체는 추측해 라벨링하지 않고 annotation 도구의 보류 상태로 표시한 뒤 difficult 속성을 남긴다.
- 동일 물체가 여러 클래스 정의를 만족하면 더 구체적인(하위) 클래스를 우선 적용한다. 현재 클래스 목록은 계층 구조가 없으므로 해당 사례가 생기면 6.4의 모호한 경계 처리 절차로 넘긴다.
- negative image(대상 인스턴스가 없는 이미지)도 포함한다. 포함 비율은 실제 데이터 수집 후 결정한다.

### 6.2 Bounding Box 기준

Bounding Box는 5.1에서 정한 대로 Polygon에서 자동 계산되므로, 아래 기준은 실제로는 6.3의 Polygon 작성을 통해 적용된다.

| 상황           | 작업 기준                                                         | 상태           |
| ------------ | ------------------------------------------------------------- | ------------ |
| 일반 물체        | 보이는 영역(visible)만 기준으로 한다(modal 방식). 가려진 부분까지 추정한 box는 만들지 않는다 | 결정           |
| 가려진 물체       | modal 방식을 따른다(보이는 영역만). 라벨링을 포기할 최소 가시 비율 수치는 표본 이미지 확보 후 결정  | 부분 결정, 검토 필요 |
| 화면 밖으로 잘린 물체 | 이미지 경계까지 표시하고 truncated 속성으로 표시한다                             | 결정           |
| 겹친 물체        | 각 인스턴스를 별도 Polygon으로 표시해 box도 각각 자동 계산되게 한다                   | 결정           |
| 작거나 흐린 물체    | 최소 pixel 크기는 카메라 해상도 확정 후 결정한다                                | 검토 필요        |
| 그림자·반사       | 물체의 불투명한 실제 표면만 포함하고 그림자·반사는 제외한다                             | 결정           |

### 6.3 Polygon·Mask 기준

| 상황        | 작업 기준                                                                         | 상태           |
| --------- | ----------------------------------------------------------------------------- | ------------ |
| 일반 경계     | 물체의 실제 외곽선을 따라 점을 찍는다. vertex 개수·간격의 정확한 기준은 도구 선택 후 결정한다                     | 부분 결정, 검토 필요 |
| 구멍이 있는 물체 | 내부 빈 영역은 별도 inner polygon(hole)으로 표현한다. 도구가 hole을 지원하지 않을 때의 대안은 도구 선택 후 결정한다 | 부분 결정, 검토 필요 |
| 가려진 물체    | 보이는 영역만 표시한다(modal 방식). 가려진 부분은 추정하지 않는다                                      | 결정           |
| 겹친 물체     | 인스턴스별로 보이는 영역만 각각 분리해 표시한다                                                    | 결정           |
| 가는 부분     | 손잡이·끈·케이블처럼 가늘고 긴 돌출부도 실제 형태를 따라 포함한다                                         | 결정           |
| 투명·반투명 물체 | 물체의 실제 외곽을 기준으로 하고 내용물이나 반사는 포함하지 않는다                                         | 결정           |
| 흐릿한 경계    | 명확히 판별할 수 없으면 difficult 속성으로 표시하고 보이는 범위 내에서 최선의 경계를 사용한다                     | 결정           |

### 6.4 모호한 경계 처리 절차

1. 작업자는 4장의 클래스 정의와 6장의 공통·유형별 기준을 먼저 적용한다.
2. 기존 기준으로 판단할 수 없으면 임의 확정하지 않고 annotation 도구에서 정한 보류 상태로 표시한다.
3. 보류 사례는 원본 이미지, 후보 클래스, 판단이 어려운 이유와 작업자 의견을 함께 기록한다.
4. 검토자가 기준을 결정하면 결정 내용을 기록하고 동일 유형 annotation을 재검수한다.

## 10. 가정

- 객체 탐지와 인스턴스 세그멘테이션은 동일한 클래스 정의를 사용한다.
- 학습 전에 annotation 결과를 변환·검증할 pipeline이 별도로 마련된다.
- 실제 운영 환경에서 수집한 대표 이미지로 작업자 calibration을 수행한다.
- 위 가정은 모두 팀 확인 전까지 확정 사항이 아니다.

## 11. 리스크

- 클래스 경계가 로봇의 처리 행동과 맞지 않으면 정확한 인식 결과도 잘못된 행동으로 이어질 수 있다.
- 시각적으로 구분하기 어려운 의미 기반 클래스를 사용하면 작업자 간 불일치가 커질 수 있다.
- Box와 Polygon 기준이 작업자마다 다르면 학습·평가 결과를 신뢰하기 어렵다.
- 클래스 ID나 schema가 중간에 바뀌면 기존 annotation의 migration 또는 재작업이 필요하다.

## 12. 관련 결정

- 현재 selected Decision 없음.
- 객체 탐지·세그멘테이션 최종 모델과 데이터 기준에 대한 팀 검토 결과를 추후 연결한다.
