# 타깃 시나리오(Target Scenario)

## 1. 요약

장기 시나리오는 이용 후 공간을 정리·점검하는 것이며, 1차 MVP는 운영자 요청부터 Dashboard 결과 표시까지의 흐름으로 둔다. 로봇은 지정 구역에서 쓰레기와 분실물 후보를 구분해 각각의 보관 위치로 옮기고 복귀한다.

## 2. 현재 기획 이해

- 로봇은 사람이 상주하지 않는 시간에도 공간을 일정 수준 이상으로 유지하는 역할을 한다.
- 제품의 1차 타깃은 무인 스터디카페다. 현재 시연은 개발센터 개발공간으로 한정한다.
- 초기 작업은 운영자 요청으로 시작한다. Dashboard와 Backend는 Mission Queue, 진행 상태, 결과 표시를 담당한다.
- 1차 MVP에서는 쓰레기는 지정 수거함으로, 분실물 후보는 별도 보관함으로 옮긴다. 분실물 분류 기준, 보관 기간, 운영자 인계 절차는 추가 논의가 필요하다.

## 3. 왜 중요한가

타깃 시나리오는 기능 범위와 기술 우선순위를 결정한다. 현재 MVP는 작업 요청, 이동, 쓰레기 수거, 분실물 별도 보관, 복귀, 결과 표시까지를 포함한다. 공간 정리, 책상 닦기, 소등, 문단속은 후속 기능으로 둔다.

## 4. 핵심 내용

### 4.1 1차 MVP 흐름 초안

1. 운영자가 Dashboard에서 대상 구역의 작업을 요청하고, Backend가 Mission Queue에 요청을 등록한다.
2. 로봇이 Mission을 할당받아 대상 구역으로 이동하고, Backend와 Dashboard에 진행 상태를 전달한다.
3. 카메라와 RGB-D 등을 활용해 사전에 정한 물체 후보를 확인한다.
4. 물체를 쓰레기, 분실물 후보, 불확실하거나 위험한 물체로 구분한다.
5. 쓰레기로 판단되고 집기 조건을 만족한 물체는 지정 수거함으로 이동한다.
6. 분실물 후보는 쓰레기 수거함과 분리된 보관함으로 이동한다. 분류 기준과 보관 후 운영 절차는 추가 정의가 필요하다.
7. 불확실하거나 위험한 물체는 건드리지 않고 사람 검토 요청으로 남긴다.
8. 작업 완료 후 로봇은 청소 후 관측을 수행하고 대기 위치로 복귀한다.
9. 로봇은 MissionReport와 전후 결과를 Backend에 전달하고, Dashboard는 최종 결과를 표시한다.

### 4.2 시연 방식 후보

- P1: 개발센터 개발공간에서 Dashboard 요청부터 결과 표시까지의 MVP 흐름을 시연한다.
- P2: 사전에 정한 쓰레기와 분실물 후보를 각각의 보관 위치로 옮기는 동작을 시연한다.
- P3: 현장 안정성에 따라 일부 이동·조작 검증은 시뮬레이션 또는 영상으로 보완할 수 있다.

### 4.3 시나리오 참여자

| 참여자     | 역할                             |
| ------- | ------------------------------ |
| 이용자     | 공간을 사용하고 퇴실하는 사람               |
| 운영자     | 무인 공간의 품질과 상태를 관리하는 사람         |
| 끌리니 로봇  | 이용 후 정리·점검 작업을 수행하는 로봇         |
| 관제 대시보드 | 운영자 요청, 진행 상태, 전후 결과를 표시하는 MVP 구성요소 |

### 4.4 작업 대상

| 구분                           | 1차 MVP 처리      |
| ---------------------------- | -------------- |
| 사전에 정한 쓰레기 물체                | 인식·분류·집기 후 지정 수거함으로 이동 |
| 분실물 후보                       | 인식·분류·집기 후 별도 보관함으로 이동 |
| 불확실하거나 위험한 물체                | 건드리지 않고 사람 검토 요청 |
| 의자·테이블 주변 정돈, 책상 표면, 조명, 출입문 | 후속 기능 후보 |
